# Sherlock: поиск сеток конкурентов через исторический SERP

## Цель
Найти сетки доменов конкурентов (кейс betify, FR) по историческим данным выдачи:
кластеризовать домены из серпа по жёстким сигналам владения и показать таймлайн-визуализацию
(колонки = даты снапшотов, строки = позиции, цвет = сетка).

## Решения (зафиксированы 2026-07-10)
- Источник данных: **Ahrefs API v3** (план Advanced, ключ рабочий, ~407k юнитов в остатке).
  DataForSEO отклонён — слишком редкие снапшоты (9 за 10 мес). Ahrefs даёт ~еженедельно.
  Эндпоинт: `GET /v3/serp-overview/serp-overview` (Keywords Explorer), параметры keyword+country+date+select+top_positions.
  НЕ rank-tracker/serp-overview — тот требует заранее заведённый проект и не даёт истории назад.
  Поведение: date → возвращает ближайший снапшот ≤ даты; дедуп по полю update_date. Глубина для betify: с ~фев 2024.
  Цена: дешёвые поля (position,type,url,title,domain_rating,update_date) не тарифицируются сверх минимума 50 юнитов/запрос.
- Масштаб пробы: **1 ключ, Франция** (например «betify», language fr).
- Шаг колонок: определяем по факту после пробного прогона.
- Жёсткие сигналы склейки в сетку: **301/302 редирект, кросс-доменный canonical, кросс-доменный hreflang**.
  Мягкие сигналы (нейминг, фавикон, синхронное появление/исчезновение) — только пометка «кандидат», без склейки.

## Факты по DataForSEO
- Эндпоинт: `POST /v3/dataforseo_labs/google/historical_serps/live`
  (keyword, location_code/name, language_code, date_from, date_to).
- Цена: **$0.00012 за один SERP-снапшот** в ответе. Проба по 1 ключу — центы.
- Оплата pay-as-you-go, без подписки (минимальное пополнение ~$50).
- Гранулярность: **месячные снапшоты**, НЕ ежедневные. Частота зависит от популярности ключа
  (ВЧ ~6–8 снапшотов/год, НЧ 1–2/год).
- Глубина истории: заявлено с ~августа 2021 (в доке Labs встречается «12 месяцев» — проверить пробой).
- Ежедневные данные возможны только «вперёд»: регулярный сбор живого серпа
  (SERP API ~$0.0006–0.002/проверка) — опциональный этап после пробы.

## Результаты пробы (2026-07-10)
- Запрос: keyword=betify, location_code=2250 (France), language_code=fr. Стоимость всего запроса — **$0.00108**.
- Отдано **9 снапшотов** за диапазон **2025-07-28 … 2026-05-27** (~10 мес). Глубина для этого ключа = ~1 год,
  НЕ до 2021 (данные Labs начинаются с момента попадания ключа в базу).
- Гранулярность нерегулярная: интервалы 1–6 недель между снапшотами.
- Каждый снапшот ~4–59 органических доменов (топ-100 позиций, включая PAA/related).
- **Главная находка:** позиция №1 ротируется В КАЖДОМ снапшоте — новое «зеркало» бренда или
  взломанный поддомен: betify.ing → betify.website → betify.univers-med.fr → betifyfr.malokadistro.com →
  betify-frcasino.eu.com → betifycasino-fr-fr.eu.com. Классический паттерн серой сетки (бан → новый домен).
- Два подтипа доменов сети: (а) **domain-mirrors** — бренд в имени домена (betify.ing, betify-fr.top);
  (б) **parasite subdomains** — поддомен betify.* на взломанном легитимном сайте (betify.univers-med.fr,
  betify.basketlandes.fr, betify2.lycee-charlesdegaulle.fr, betifyfr.malokadistro.com).
- Прототип визуализации: build_viz.py → data/betify_fr_timeline.html (подсветка пока ЭВРИСТИЧЕСКАЯ по неймингу).

## Этап 1 — жёсткая склейка по активным редиректам (СДЕЛАНО 2026-07-10)
- redirect_probe.py: Googlebot UA, следует цепочке HTTP 3xx + meta-refresh + JS-regex (без выполнения чужого JS),
  SSL не верифицируется, резюмируемый, инкрем. запись. Вывод data/redirects.json.
- Проверено **1254 уникальных хоста** из выдачи (1 представитель на хост).
  142 редиректят на другой хост, **236 мёртвых** (→ отложены на Wayback-этап).
- cluster_redirects.py: union-find по рёбрам host->host, транзитивно (a→b→c→d = одна сеть).
  Фильтр «сеть = ≥2 разных регистрируемых домена» (иначе www/поддомен одного сайта). Вывод data/clusters.json.
- Результат: **73 подтверждённые межсайтовые сети**. Таймлайн перекрашен: цвет = сеть, белый = без редиректа/мёртвый.
- Заметные betify-сети: C3 (взломанные FR-сайты lycee-charlesdegaulle/retdtechfrance/charlicharger → cesar-group.fr),
  C5 (betify.ing/.mobi → betifyme1.com), C8 (betifycasino.com/.fr/1/2 → betifycasino2.fr),
  C11 (betify-casino.fr/betify-officiel.fr → sh5.betify-officiel1.fr), C2 (betify.partners/sitegpr/bit.ly → betify2.so).
  Также непрофильные сети в той же выдаче: C1 flashscore/soccerway, C4 crypto-casino.bet, C7 please-casino.
- Артефакты: redirect_probe.py, cluster_redirects.py, data/redirects.json, data/clusters.json.
- Нормализация: www и без-www = один хост (http->https не ребро).
- ПРАВИЛО approved-source (v2): ребро засчитывается только если редирект исходит из корня сайта/поддомена
  или целевой страницы из СЕРПа. Промежуточные глубокие пути (аффилейт-прокладки, напр. sitegpr.com/go/betify) — НЕ ребро.
- GRAPH-AWARE (двухпроходно): глубокий-путь хоп a->b засчитываем, если b сам источник строгого ребра
  (его корень независимо редиректит в сеть). Возвращает легит-цепочки через /path, но не аффилейт-прокладки.
- Краулер v2 (seeds): probe КОРНЕЙ доменов/поддоменов + целевых URL из СЕРПа + раскрытие промежуточных хостов.
  2755 проб. redirects.json теперь {"probes": {seed_url: {chain,...}}}. Старый формат — redirects.v1.bak.json.
- Итог: 78 сетей. C1 cesar-group = 6 доменов (retdtechfrance вернулся + найден новый marcus-strasbourg.fr через root-краулинг),
  C3 = аффилейт-инфра betify (betify123/betify2.so/bit.ly/record.betify.partners) БЕЗ sitegpr.
- Аудит: под каждой диаграммой сырые цепочки (корень+SERP-URL), прокладочные хопы зачёркнуты.
- Визуализация: build_app.py -> data/app.html — ЕДИНЫЙ интерфейс с верхними табами
  «Таблица по датам» / «Диаграммы сетей». Цвет сети общий (HSL->hex, golden-angle).
  Клик по цветной ячейке в таблице открывает Graphviz-блок-схему этой сети (dot, узлы в цвете сети,
  подписи рёбер 301/302/meta/JS, конечный домен выделен рамкой). graph_networks.py — отдельная версия только графов.

## Этап 2 — canonical + hreflang (в работе, механизм определён)
- ДВОЙНОЙ UA (Googlebot+браузер) ОТКЛОНЁН пользователем: клоакинг по IP, наш fetch с любым UA покажет не то, что видит Google. Вводит в заблуждение.
- ДОСТОВЕРНЫЙ источник — только **RRT (search.google.com/test/rich-results)**: фетчит реальным Googlebot с IP Google.
- Механизм (замерен): работает в ЗАЛОГИНЕННОМ Chrome пользователя через claude-in-chrome MCP (аноним/in-app браузер — стена логина).
  Флоу на домен: ввод URL в поле результата → Enter → ждать ~12с краул → «View tested page» →
  1 JS-вызов извлекает canonical/hreflang из CodeMirror: `[...document.querySelectorAll('.CodeMirror')].map(e=>e.CodeMirror).filter(Boolean)` берём с макс. getValue(), regex по <link rel=canonical> и <link ... hreflang>.
  НЕ через clipboard (навигатор.clipboard.readText зависает на разрешении) и НЕ ручным поиском.
  ~30–45 сек/домен. Капчи за 2 теста не было; троттлинг-порог неизвестен. Все 894 нереально — только батчами.
- ПРАВИЛО (уточнение пользователя): если canonical/hreflang ведёт на СОБСТВЕННЫЙ ПОДДОМЕН —
  поддомен считаем ОТДЕЛЬНЫМ УЗЛОМ, рисуем ребро родитель→поддомен (метка canonical/hreflang), выделяем как сетку И красим,
  даже если регистрируемый домен один. Ослабить фильтр «≥2 регистр. домена»: компонент = сеть, если есть хотя бы одно
  canonical/hreflang-ребро между разными хостами ИЛИ ≥2 регистр. домена.
- Цель: кросс-доменные canonical/hreflang → рёбра в сети (как редиректы).
- ОХВАТ (уточнение): прогоняем через RRT ВСЕ домены, даже с существующим 301 (могут иметь и редирект, и canonical/hreflang).
  Нюанс: RRT следует за 301 и отдаёт HTML КОНЕЧНОЙ страницы (у 301 нет тела) — canonical/hreflang вешаем на реально отрендеренный хост.
- МУЛЬТИ-СИГНАЛ: ребро (a→b) несёт МНОЖЕСТВО меток, в подписи через запятую: «301, canonical», «canonical, hreflang», «JS, canonical».
  Редирект-метки (301/302/meta/JS) + canonical + hreflang сливаются на одном ребре. Направление: источник→цель.
- Извлечение: JS-чтение CodeMirror `[...document.querySelectorAll('.CodeMirror')].map(e=>e.CodeMirror)` с макс. getValue() → regex canonical/hreflang.
  Флоу: navigate `?url=<enc>` (авто-запуск) → 1 await-JS (поллинг краула + клик View + extract). ~2 вызова/домен.
- БАТЧ 1 (50 доменов) СДЕЛАН, результаты data/rrt_batch1.json. КАПЧИ/ТРОТТЛИНГА НЕТ (0/50) → весь набор проходим.
  43 ok, 7 crawl-failed (блокируют Googlebot = агрессивный клоакинг: betify.site, betifyfrance.com, betify.ola.click,
  affiliates.betify.partners, betify-fr.net, betify-france.fr, betifyy.fr). 18 доменов дали canonical/hreflang-рёбра.
  Вердикт: canonical/hreflang НЕ прячут — совпадают с редиректами (перекрёстное подтверждение). 3 новых домена:
  ambulance-zephyr.fr (взлом. сайт скорой, C11), betify.it (C9), betifypro.com (C16).
- ИНТЕГРАЦИЯ СДЕЛАНА: cluster_redirects.py читает data/rrt_batch*.json, сливает метки на рёбрах (мульти-сигнал,
  напр. «301, canonical, hreflang» — 16 таких), правило поддомен-узлов (фильтр сети ослаблен: >=2 регистр. ИЛИ есть canon/hreflang-ребро).
  build_app.py берёт рёбра из clusters.json. Всё в data/app.html.
- ОСТАЛОСЬ: решить масштаб RRT (батчи 2+ по остальным ~844 доменам) — троттлинга нет, ограничение только время (~30с/домен).

## Проба DataForSEO (архив)
1. **Проба** — [x] СДЕЛАНО. См. «Результаты пробы» выше.
2. **Сбор** — снапшоты → SQLite (таблицы: snapshots, serp_items, domains).
3. **Граф доменов** — уникальные домены, таймлайн входа/выхода из топа.
4. **Сбор улик** по каждому домену:
   - живой чек: curl → цепочка редиректов, canonical, hreflang (текущее состояние);
   - Wayback CDX API (бесплатно) → исторические статус-коды/Location/HTML по датам;
   - хранить улики с датой и источником.
5. **Кластеризация** — union-find по жёстким рёбрам; каждой сетке — цвет.
6. **Визуализация** — HTML (как референс-скрин): колонки-даты, домены с подсветкой сетки,
   тултип с уликой склейки.

## Узкие места
- Месячная гранулярность: резкие смены доменов внутри месяца не видны.
- 301 «сейчас» ≠ 301 «тогда»: мёртвые домены проверяем только через Wayback,
  покрытие серых казино-доменов в архиве дырявое.
- Глубина истории Labs-эндпоинта: 12 мес или до 2021 — выяснит проба.
- Склейка только по жёстким сигналам ⇒ возможна фрагментация сетки (недокластеризация) — осознанно.
